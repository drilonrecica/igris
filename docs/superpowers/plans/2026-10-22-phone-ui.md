# Phone UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the web UI served by `igris serve` as the phone page the design describes: one glance answers "does it need me" and "how far", a Needs-you sheet at the thumb, a plan page, the brand's look in dark and light.

**Architecture:** The Go side (`internal/serve/ui.go`) keeps rendering `html/template` pages from the snapshot and gains a view model for the status word, the phase bar and the sheet; the template, stylesheet and script are rewritten in place; two new routes (`/plan`, `/plan/live`) and four static files (two fonts, the icon, the favicon alias) are added. Live updates, the no-JS forms, the CSP and every pinned test contract stay as they are.

**Tech Stack:** Go 1.27 standard library (`embed`, `html/template`, `net/http`), one CSS file, one classic-JS file, Chakra Petch woff2 (OFL, already in `site/fonts/`).

**Spec:** `docs/superpowers/specs/2026-10-22-phone-ui-design.md`

## Global Constraints

- CSP stays `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; form-action 'self'; frame-ancestors 'none'; base-uri 'none'` plus exactly one addition, `font-src 'self'`. No inline `style=`, `<style>`, inline script or `on*=` attributes anywhere (`TestUIPagesKeepTheCSPAndNoYolo`).
- No new dependency, no build step, nothing loaded from elsewhere. One template file, one stylesheet, one script.
- `yolo` and `plan:yolo` are never offered: `remoteModes` stays the only mode list the templates see.
- Form contract unchanged: `<form method="post" action="/act" class="cmd[ danger]"[ data-confirm="1"]>`, hidden fields `csrf`, `type`, `task`, `question`, `plan`, `continue`, `yes`, at most one `text` field, `button.go`, and for stop/skip/done a `div.confirm` with `button[name=confirmed][value=1]` and `button.cancel`.
- Markup the script and tests match stays: `#live`, `#conn`, `#flash`, `form.cmd`, `section.question`, `.actions`, `details`, `section[aria-label='Run mode']`, `pre.tail[data-task]`, `.ran[data-started]`, `time[datetime]`, `meta[name="igris-csrf"]`, the single `<script src="/static/app.js" defer>`.
- Red (`--plume`, `--needs-text`) is used only for Needs you (word, segment, sheet label and edge, the gate's `you`) and the Stop button's text.
- Copy is igris's: `Pause after this task`, `Resume`, `Stop`, `Stop igris?`, `Leave uncommitted`, `Retry fresh`, `Retry, continuing the conversation`, `Approve: the session switches to <mode>`, `Reject with feedback`, `Mark done`, `Skip`.
- Touch targets ≥ 44 px; text contrast ≥ 4.5:1 in both themes; every state also a word.
- Tests only inside the fence, one at a time: `systemd-run --user --scope -q -p MemoryMax=6G -p MemorySwapMax=0 -p TasksMax=400 go test -race -timeout 120s ./internal/serve/`. Commit messages `V16-R: <summary>`.

## Review Focus

1. A run with no active task yet (`Run != ""`, `Active` empty, not ended) must show `Waiting`, not `Working` or an empty word. Test in Task 3.
2. A parallel phase with two active tasks where one has a question and the other is working must show `Needs you` with `1 question`, one sheet, two cards. Test in Task 3 (`running` fixture has exactly this).
3. The ended page rendered by the server (reload after the end) and the page `ended()` produces in the browser must agree: no forms, no sheet, no bar, the word from `End`. Test in Task 4 (`ended.html` golden) and Task 6 (the `gone` list).
4. A question for a task that has no card (the reset request) must still get the sheet, so the first screen never says `Needs you` with nothing to tap. Test in Task 3.
5. Without JavaScript, Skip and Reject must be completable: their text fields are in the markup and visible. Test in Task 4 (golden contains `<textarea name="text"` inside the sheet's reject form and the skip form's `<input type="text"`, outside any `[hidden]`).
