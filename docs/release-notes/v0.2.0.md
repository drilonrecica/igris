**igris** runs the tasks in your markdown project plan one at a time, each in a fresh Claude Code session, started with exactly the model your plan assigns to that task.

v0.2.0 gives igris a front door. Run `igris` in a terminal and you get a home screen: your phases and their progress, what runs next and on which rank, the health of your setup and your recent runs, with a button for everything you can do. New commands (`doctor`, `history`, `completion`) cover the same ground from the command line, and Homebrew is now an install option. No change to the plan format, config keys or file formats.

## Highlights

- **A home screen.** Bare `igris` opens it. Preview a run, check the plan, open the doctor, read the history, view the settings, edit the plan in `$EDITOR`, adapt a plan igris can't read, send a test notification, then start a run, all without leaving the app. It stacks into one column on a phone-width terminal. See the [README](https://github.com/drilonrecica/igris#home-screen).
- **Onboarding in the app.** In a folder with no `igris.toml` the home screen walks you through init, the example plan, check, preview and your first run.
- **`igris doctor`.** One line per check of your machine and project, and the command that fixes each problem. It never changes anything.
- **`igris history`.** What ran, what finished, how long it took and how each run ended. `igris status` also shows the current run.
- **Shell completions.** `igris completion bash|zsh|fish` completes subcommands, flags and the phase and task IDs of your plan.
- **A run view that tells you more.** The current task's card shows what the task is about, `t` (or one click on any task) opens its full details, and when a session needs you the card says `o` opens it.
- **Copy with `y`** (OSC 52), including over SSH: the `claude --resume` command of the current session, a log line, the adapt proposal's path.
- **A clearer adapt review**, comparing your plan and the proposal table by table. And a plan convention for work that waits on something outside it: a `user` task that names the blocker.
- **Homebrew.** `brew install drilonrecica/tap/igris`.

## Upgrade

```sh
brew install drilonrecica/tap/igris        # or: brew upgrade igris
go install github.com/drilonrecica/igris/cmd/igris@v0.2.0
```

Or download the archive for your platform below, check it against `checksums.txt`, and put the binary on your `PATH`:

```sh
sha256sum --ignore-missing -c checksums.txt    # macOS: shasum -a 256 --ignore-missing -c checksums.txt
tar xzf igris_0.2.0_<os>_<arch>.tar.gz
install -m 755 igris ~/.local/bin/igris
igris version
```

A run interrupted under v0.1.x resumes normally under v0.2.0.

## Behavior changes

- **Bare `igris` on a terminal opens the home screen** instead of printing the help. Piped, scripted or under cron (stdin or stdout not a terminal, stdin `/dev/null`, `TERM=dumb`) it still prints the help and exits 2. `igris help` always prints it.
- **`igris arise` with no phase and nothing to resume** opens the start-run wizard on a terminal instead of exiting 1. With `--no-tui`, `--dry-run` or without a terminal it behaves as before; `igris arise PHASE` is unchanged.

## Good to know

- The first session in a folder Claude Code hasn't seen waits on its folder-trust prompt; igris shows "needs you". Open the session and answer it once.
- `accept` mode still asks before Bash commands, which is Claude Code's behavior.
- After you quit, `igris status` keeps showing the last run: that is the resume state.

## Known limitations

- herdr only; a tmux backend is planned.
- Linux and macOS; Windows through WSL2 only, not yet verified on a real Windows machine.
- Release artifacts are not signed (SHA-256 checksums only).
