**igris** runs the tasks in your markdown project plan one at a time, each in a fresh Claude Code session, started with exactly the model your plan assigns to that task.

v0.3.0 brings tmux. Run igris inside tmux and every task gets its own tmux window, just as it gets a herdr tab inside herdr. igris also learns what Claude Code is doing (working, waiting for you, idle) from Claude Code's own hooks, so it no longer depends on herdr's integration for that. No change to the plan format.

## Highlights

- **tmux backend.** Inside tmux 3.2 or newer, each session opens in a background window named `<task> · <rank>`. `o` switches to it, toasts show in tmux's status line, and everything survives a detach and an SSH reconnect. See [tmux setup](https://github.com/drilonrecica/igris#tmux-setup).
- **`backend = "auto"`.** New projects pick herdr inside a herdr pane and tmux inside tmux, with no setting to change. Existing `backend = "herdr"` configs keep working.
- **Agent state from Claude Code hooks.** Each session gets a small hooks-only settings file (`--settings`), so igris knows when a session is blocked on a question or permission prompt, idle, or gone. It works in tmux, and in herdr with or without herdr's Claude integration. Nothing is added to your `.claude/` settings, and the hook state only drives **Needs you**: a task still advances only on `igris done` or your action.
- **One test suite for every backend.** fake, herdr and tmux pass the same conformance tests, so the next multiplexer has a bar to meet.

## Upgrade

```sh
brew upgrade igris                         # or: brew install drilonrecica/tap/igris
go install github.com/drilonrecica/igris/cmd/igris@v0.3.0
```

Or download the archive for your platform below, check it against `checksums.txt`, and put the binary on your `PATH`:

```sh
sha256sum --ignore-missing -c checksums.txt    # macOS: shasum -a 256 --ignore-missing -c checksums.txt
tar xzf igris_0.3.0_<os>_<arch>.tar.gz
install -m 755 igris ~/.local/bin/igris
igris version
```

A run interrupted under v0.2.x resumes normally under v0.3.0 in the same multiplexer. Resumed under the other one (started in herdr, resumed in tmux), the old session can't be reattached, and igris offers to continue the conversation, start fresh, mark it done, skip it or stop.

## Behavior changes

- **The default backend is `auto`.** Without a `backend` key, igris now uses tmux when it runs in tmux. Inside herdr nothing changes.
- **`igris doctor --json`:** the check `herdr-available` is now `backend`, and the version check covers the backend you run in (`herdr` or `tmux`).
- **A missing herdr integration is no longer a warning.** igris reads the agent state from hooks without it.

## Good to know

- In a folder Claude Code hasn't seen, the first session waits on its folder-trust question. No hook fires until you answer it, so after about 15 seconds igris holds the task prompt and shows **Needs you**. Open the window, answer once, and the prompt goes out by itself.
- Inside tmux running inside herdr, `auto` picks herdr. Set `backend = "tmux"` to override.
- The tmux backend was verified on Linux (tmux 3.7c, Claude Code 2.1.293). The macOS tmux smoke run is still open.

## Known limitations

- Linux and macOS; Windows through WSL2 only, not yet verified on a real Windows machine.
- Release artifacts are not signed (SHA-256 checksums only).
