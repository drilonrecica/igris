**igris** runs the tasks in your markdown project plan one at a time, each in a fresh Claude Code session, started with exactly the model your plan assigns to that task. Since 1.5, in a phase you mark parallel, it runs independent tasks side by side. Since 1.6 you can follow a run and answer its questions from your phone.

igris 1.11 puts several projects behind one page and helps you write tasks an agent can run. There is no 1.10 release: what was built as 1.10 ships here too. It only adds to 1.9 apart from a renamed cookie that moves over by itself: plans, `--json`, the run log, the webhook payload and your templates need no changes ([`docs/compatibility.md`](https://github.com/drilonrecica/igris/blob/v1.11.0/docs/compatibility.md)).

## What's new

- **[`igris hub`](https://drilonrecica.github.io/igris/docs/several-projects.html#one-page-for-all-your-runs):** `igris hub --all --http 100.101.102.103:7777` follows every live run, and the ones you start later, with one listener, one pairing and one QR code. `/` lists the runs, most urgent first, with one sheet for the questions of every project; a run's page is the page `igris serve` draws. `igris hub PATH...` takes only those projects. Manage only: starting a run stays in the terminal, skip-permissions mode is never offered, and ending the hub never stops a run.
- **A wide layout for a laptop.** At 64rem and wider the hub is two panes (the runs at the left, the selected run at the right) with the questions in a side panel, and a run page lays its cards in a grid. Reach the hub from a MacBook over Tailscale or `ssh -L` and pair by copying the URL. `j`/`k` move between runs.
- **ntfy's Open goes through the hub** when one is running and follows the project.
- **A run registry** in the runtime directory (`$XDG_RUNTIME_DIR/igris/runs/`), which the hub reads; nothing is added to your home but the hub's token (`~/.local/state/igris/hub-token`).
- **Arise.** `igris arise --dry-run --prompts` shows the exact first prompt of every session before you start, real paths and handoff notes included.
- **Four more `igris check --strict` hints for agent-ready tasks:** `spec`, `verify`, `deps` and `words` (a Task cell over 250 words).
- **`igris history --stats`:** per rank the mean attempts, the verify-fail rate and the agent and Needs-you time, and a `rewrite:` line for each task that keeps taking two or more attempts. `--json` has a schema.
- **The parallel marker.** In a parallel phase a task that would start alongside others says so, `with B-2, B-3`, in the TUI, the Preview, Phase detail and the web plan page.
- **`igris status --since-last-run`:** what changed in the plan between runs, from a baseline (`.igris/plan-cells.json`) a run keeps.
- **Working hours:** `[run] hours = "09:00-22:00"`. Outside the window no agent task starts; user tasks start and running sessions go on. Shown as a hold, `Paused · outside hours · resumes 09:00`.
- **Glyphs as words:** `[tui] screen_reader = true` (or `IGRIS_SCREEN_READER=1`) makes the command line's text say `needs you M1-03` for `! M1-03`, and `1 of 3 done` for a bar.
- **A high-contrast theme:** `[tui] theme = "high-contrast"`, black and white at 7:1 (WCAG AAA) for the TUI, the command line and the web UI.
- **[In a box](https://drilonrecica.github.io/igris/docs/container.html):** a container recipe (`examples/container/`) for skip-permissions runs.
- Fixed: two projects served on one address no longer unpair each other. The web UI's cookie is now `igris_token_<h>`, one per project.
- Fixed: a session's last lines on a web UI card no longer skip a refresh now and then (since 1.4).
- Fixed: `igris phases` and the dry run's summary now agree with the scheduler about `Group`: tasks sharing a Group never run together, and a phase without the parallel marker has no `together` sets.
- Fixed: `igris doctor` suggests `igris init --example` for a missing plan, not `igris adapt`.

## Upgrade

Install the new igris and you are done: nothing in your plan, `igris.toml`, scripts or `.igris/` needs to change, and a run interrupted under 1.9 resumes. `igris update` does it for you. Stop a run (`igris stop`) before you update the igris that is hosting it. From 0.x, run `igris config migrate` once in each project first; see the [upgrade guide](https://drilonrecica.github.io/igris/docs/upgrade.html).

Three things to know. A config that sets `[run] hours`, `[tui] screen_reader` or `[tui] theme = "high-contrast"` is refused by igris 1.0–1.9 (an unknown key or an invalid value), so such a config needs 1.11 wherever it runs. Finish a run before going back to 1.9; `.igris/plan-cells.json` and the run-log events `hours_hold` and `hours_resume` are ignored by it. A phone paired with a project's web UI under 1.9 doesn't pair again: the first time it opens the page, the old cookie `igris_token` is accepted and moved to the new one. That works through 1.11.x; igris 1.12 stops accepting the old name, so a phone not opened during 1.11 pairs again with `igris serve token`. And `igris hub` and the run registry are unknown to igris 1.0–1.9: a hub follows only runs hosted by 1.11, so update the igris that hosts a run before you point a hub at it.

Homebrew:

```sh
brew upgrade igris                         # or: brew install drilonrecica/tap/igris
```

Or `go install github.com/drilonrecica/igris/cmd/igris@v1.11.0`, or download the archive for your platform below, with `checksums.txt` and `checksums.txt.sig`, and verify them:

```sh
curl -fsSLO https://raw.githubusercontent.com/drilonrecica/igris/v1.11.0/allowed_signers
ssh-keygen -Y verify -f allowed_signers -I igris -n file -s checksums.txt.sig < checksums.txt
sha256sum --ignore-missing -c checksums.txt    # macOS: shasum -a 256 --ignore-missing -c checksums.txt
tar xzf igris_1.11.0_<os>_<arch>.tar.gz
install -m 755 igris ~/.local/bin/igris
igris version
```

The first command must print `Good "file" signature for igris`.

The editor extension is unchanged in 1.11: install `drilonrecica.igris` from your editor's extension view, or `code --install-extension igris-1.11.0.vsix` with the file attached below.
