**igris** runs the tasks in your markdown project plan one at a time, each in a fresh Claude Code session, started with exactly the model your plan assigns to that task.

v1.0.0-rc.2 is the second release candidate for igris 1.0. It carries the fixes from the final security review and adds the docs pages on the project site. What 1.0 promises is unchanged from [rc.1](https://github.com/drilonrecica/igris/releases/tag/v1.0.0-rc.1) ([`docs/compatibility.md`](https://github.com/drilonrecica/igris/blob/v1.0.0-rc.2/docs/compatibility.md)), with one exception: config validation got stricter before it freezes.

## Check your config

A few configs that rc.1 accepted are now rejected. Run `igris check` in each project; it names the key to fix.

- `claude.extra_args` with a flag that changes the session's tools, permissions, directory, system prompt or shape: `--allowedTools`, `--disallowedTools`, `--tools`, `--add-dir`, `--permission-prompt-tool`, `--bare`, `--setting-sources`, `--plugin-dir`, `--plugin-url`, `--mcp-config`, `--strict-mcp-config`, `--agent`, `--agents`, `--system-prompt`, `--system-prompt-snapshot`, `--ide`, `--worktree`/`-w`, `--fork-session`, `--no-session-persistence`. igris decides these for each task; a config shouldn't be able to widen them.
- A control character in a `claude.extra_args` value or in a `[models]` rank or model.
- `notify.ntfy.server` or `notify.gotify.server` with a `user:password@` part. Use `token`.
- An `igris.toml` that isn't a regular file or is over 1 MiB, and a plan over 16 MiB.

## Security fixes

- **Reattach is bound to the task's own pane.** A session could rewrite `state.json` so that the next `igris arise` reattached to another pane (your shell, say) and typed the task prompt there. Backends now reattach only to the pane they started for that task, and the held prompt is rebuilt from the plan.
- **A config changed during a run is no longer used silently.** igris ignores edits to `igris.toml` while it runs, but the next run used them without a word. Now the next `arise` shows a warning and asks first; `check` and `doctor` warn meanwhile. Unattended scripts exit 1 at that question until someone confirms once.
- `doctor` also reads `.claude/settings.json`, and warns about a rule that allows every shell command or a `defaultMode` that bypasses prompts.
- The plan, `igris.toml`, `state.json` and the lock are read as bounded regular files, so a FIFO in their place can't hang igris.
- Text cleaning also strips invisible format characters that a terminal doesn't show but a model reads.

Details: [`docs/threat-model.md`](https://github.com/drilonrecica/igris/blob/v1.0.0-rc.2/docs/threat-model.md).

## Upgrade

Homebrew stays on 0.6.0 until 1.0.0. To try the candidate:

```sh
go install github.com/drilonrecica/igris/cmd/igris@v1.0.0-rc.2
```

Or download the archive for your platform below, with `checksums.txt` and `checksums.txt.sig`, and verify them:

```sh
curl -fsSLO https://raw.githubusercontent.com/drilonrecica/igris/v1.0.0-rc.2/allowed_signers
ssh-keygen -Y verify -f allowed_signers -I igris -n file -s checksums.txt.sig < checksums.txt
sha256sum --ignore-missing -c checksums.txt    # macOS: shasum -a 256 --ignore-missing -c checksums.txt
tar xzf igris_1.0.0-rc.2_<os>_<arch>.tar.gz
install -m 755 igris ~/.local/bin/igris
igris version
```

The first command must print `Good "file" signature for igris`. Coming from 0.x, also run `igris config migrate` once per project (see rc.1's notes).
