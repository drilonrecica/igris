**igris** runs the tasks in your markdown project plan one at a time, each in a fresh Claude Code session, started with exactly the model your plan assigns to that task.

v1.0.0-rc.1 is the first release candidate for igris 1.0. It adds no features. It decides what 1.0 promises not to break, writes it down, and tests it, and it makes the few breaking changes that had to come before that promise. Try it on your projects and report anything that breaks: what this release freezes is what 1.x keeps.

## What 1.0 promises

From 1.0 until 2.0, these keep working unchanged ([SPEC §19](https://github.com/drilonrecica/igris/blob/v1.0.0-rc.1/SPEC.md#19-compatibility)). 1.x may add to them, never remove or change them:

- **The plan format**, now on its own page: [`docs/plan-format.md`](https://github.com/drilonrecica/igris/blob/v1.0.0-rc.1/docs/plan-format.md). A plan may say `<!-- igris:format 1 -->`; it never has to.
- **`igris.toml`**: keys, defaults and validation.
- **The CLI**: commands, flags, arguments, and exit codes (`0` success, `1` failure, `2` usage error, `3`–`9` reserved), with what exits `1` for each command in SPEC §14.
- **`--json`** of `check`, `phases`, `status`, `history`, `report` and `doctor`, each with a JSON schema in [`docs/json/`](https://github.com/drilonrecica/igris/tree/v1.0.0-rc.1/docs/json).
- **`igris done`, `skip` and `reset`** and the signal files they write, **`.igris/`** with `state.json` and the run log, the **template variables**, the **generic webhook** (payload and headers) and the **task-hook environment** (`IGRIS_*`).

Not promised: the TUI, the default prompt's wording, text output, and igris's Go packages.

A **compatibility suite** keeps the promise honest: the configs, plans and signal files every release from 0.1.0 to 0.6.0 wrote, captured by building each release from its tag, plus the state files and run logs of each format, all checked on every change.

## Upgrade

Homebrew stays on 0.6.0 until 1.0.0. To try the candidate:

```sh
go install github.com/drilonrecica/igris/cmd/igris@v1.0.0-rc.1
```

Or download the archive for your platform below, with `checksums.txt` and `checksums.txt.sig`, verify them, and put the binary on your `PATH`:

```sh
curl -fsSLO https://raw.githubusercontent.com/drilonrecica/igris/v1.0.0-rc.1/allowed_signers
ssh-keygen -Y verify -f allowed_signers -I igris -n file -s checksums.txt.sig < checksums.txt
sha256sum --ignore-missing -c checksums.txt    # macOS: shasum -a 256 --ignore-missing -c checksums.txt
tar xzf igris_1.0.0-rc.1_<os>_<arch>.tar.gz
install -m 755 igris ~/.local/bin/igris
igris version
```

The first command must print `Good "file" signature for igris`. Check that `allowed_signers` holds the key printed in the README's [Verifying a download](https://github.com/drilonrecica/igris#verifying-a-download).

Then, in each project:

```sh
igris config migrate     # once: removes claude.command, which every igris init before 0.7 wrote
igris check
```

`config migrate` shows the line it removes, asks first and keeps a backup in `.igris/config/`. The config's hash doesn't change, so a run interrupted under 0.6 resumes.

## Behavior changes

- **`claude.command` is removed.** It never did anything (igris starts `claude` from your `PATH`). A config that still has it stops `check`, `arise` and `doctor` with `claude.command was removed in 0.7 …; run igris config migrate`.
- **`--json` changed** (scripts need updating): every output starts with `"v": 1`; `doctor` prints `{"v": 1, "checks": [...]}` instead of an array; an empty rank or mode is left out instead of `"—"`; the count key `in progress` is `in_progress`; pending signals are `{"task", "action"}` objects. Readers should ignore fields they don't know.
- **Exit codes**: a malformed task ID in `done`/`skip` and an unknown `notify test --event` exit `2` (usage error), not `1`. `adapt` stopped with Ctrl-C exits `0`, like `arise`.
- **Help**: `igris help COMMAND` shows that command's help; `-h` output goes to stdout.
- **`state.json` is version 3.** Older state is read and upgraded. A state file from a newer igris says to upgrade, a damaged one says it is damaged. igris 0.6 can't read version 3: finish the run or delete `.igris/state.json` before going back.
- **A plan marked with a newer format** (`<!-- igris:format 2 -->`) gets one error, `plan format 2 needs a newer igris`, and igris suggests upgrading instead of `igris adapt`.

## Known limitations

- Linux and macOS; Windows through WSL2 only, not yet verified on a real Windows machine.
- On a public ntfy server without a token, the topic is the only protection: use a long random one, or set a token.
