**igris** runs the tasks in your markdown project plan one at a time, each in a fresh Claude Code session, started with exactly the model your plan assigns to that task. Since 1.5, in a phase you mark parallel, it runs independent tasks side by side. Since 1.6 you can follow a run and answer its questions from your phone.

igris 1.6 adds to 1.5 and breaks nothing. Nothing listens on the network until you set an address; plans, `igris.toml` and scripts written for 1.0 to 1.5 need no changes ([`docs/compatibility.md`](https://github.com/drilonrecica/igris/blob/v1.6.0/docs/compatibility.md)).

## What's new

- **Control from your phone.** Set `[serve] http` to a Tailscale or loopback address (`igris serve --http` for one run), run `igris serve token` and scan the QR code: a web page follows the run, shows every active task's tail and answers questions, approves or rejects plans, pauses, stops, retries, marks done and skips. Stop, skip and done ask twice. [Control from your phone](https://drilonrecica.github.io/igris/docs/control-from-your-phone.html).
  - Loopback (`ssh -L`) and Tailscale addresses bind directly; anything else needs `--listen-public` with `tls_cert` and `tls_key`. `igris serve token --rotate` unpairs every device.
  - **Skip-permissions mode is never offered and the API refuses it.** It still needs the typed phrase at a terminal.
- **ntfy answer buttons.** `[notify.ntfy] actions = true` puts `Commit`/`Don't commit`, `Skip`/`Keep`, `Retry`/`Stop` or `Approve`/`Open` on a question's message. A button answers that one question, once, within 10 minutes, with a token that is never your owner token.
- The commit question now notifies as `needs_input`, like every other question.
- Additive only: `[serve]` in `igris.toml`, `serve --http`, `--listen-public`, `serve token`, `.igris/serve-token`, the HTTP mapping of protocol 1. The web UI's pages are not part of the 1.x promise; the API is.

## What it costs

There is no relay: your phone reaches your machine directly, over Tailscale or an ssh tunnel you run. **Whoever holds the pairing token controls the run**, short of skip-permissions mode, until you rotate it, so treat the URL and QR code like a password. A browser sends its cookie to every port of the listener's host, and `100.64.0.0/10` is the whole carrier-grade NAT range; both are recorded as accepted risks in [`docs/threat-model.md`](https://github.com/drilonrecica/igris/blob/v1.6.0/docs/threat-model.md), which also lists what the pre-release security review fixed.

## Upgrade

From 1.0 to 1.2 there is nothing to do but install; `igris update` does it for you from 1.2. From 0.x, run `igris config migrate` once in each project first; see the [upgrade guide](https://drilonrecica.github.io/igris/docs/upgrade.html). Stop a run (`igris stop`) before you update the igris that is hosting it, or it keeps the old one until it ends.

Homebrew:

```sh
brew upgrade igris                         # or: brew install drilonrecica/tap/igris
```

Or `go install github.com/drilonrecica/igris/cmd/igris@v1.6.0`, or download the archive for your platform below, with `checksums.txt` and `checksums.txt.sig`, and verify them:

```sh
curl -fsSLO https://raw.githubusercontent.com/drilonrecica/igris/v1.6.0/allowed_signers
ssh-keygen -Y verify -f allowed_signers -I igris -n file -s checksums.txt.sig < checksums.txt
sha256sum --ignore-missing -c checksums.txt    # macOS: shasum -a 256 --ignore-missing -c checksums.txt
tar xzf igris_1.6.0_<os>_<arch>.tar.gz
install -m 755 igris ~/.local/bin/igris
igris version
```

The first command must print `Good "file" signature for igris`.
