**igris** runs the tasks in your markdown project plan one at a time, each in a fresh Claude Code session, started with exactly the model your plan assigns to that task.

v0.4.0 lets your plan say more about each task: which checks to run when it's done, how long it should take, and which files the session must read first. igris can also run just part of a plan, put a task back, run your own commands around every session, and lint a plan for CI. Everything is optional: no plan migration is needed.

## Highlights

- **Verify profiles.** Name your checks in `igris.toml` (`[verify] fast = "go test ./internal/..."`, `full = "make fmt lint test"`), give a phase its own with `[phases.<id>] verify`, and pick one per task with the new `Verify` column, or `none` to skip. Plans name profiles, never commands. `run.verify` keeps working as the profile `default`. See [Verification and commits](https://github.com/drilonrecica/igris#verification-and-commits).
- **Timeout column.** `45m`, `1h30m`: a session running longer is marked **overdue**, raises **Needs you** and sends the new `task_overdue` notification, once per attempt. igris never stops the session for it.
- **Context column.** Repo-relative files and directories the session reads before changing anything, listed in the task prompt as required reading. igris names the paths and never sends their contents; every path must exist inside the project.
- **Run a slice.** `igris arise --only M1-03,M1-05`, `--from M1-03`, `--until M2-02`. Dependencies still count: a slice task that waits on unfinished work is reported as `not run`, never forced. A bare `arise` resumes the same slice.
- **`igris reset ID [--force]`.** Put a task back to `ready` or `blocked` to run it again, with or without an igris running. Resetting the task igris is on closes its session and pauses the run.
- **Task hooks.** `[hooks] before_task` / `after_task` run your own commands (argv lists, no shell) around every agent session, e.g. to start a dev database. A failing `before_task` opens no session and asks you what to do.
- **`igris check --strict`.** Lints the plan (missing bold titles, overlong rows, gates that miss tasks of their phase, `yolo` rows, …) and exits 1 on any plan or config warning. Machine warnings never fail it, so it runs in CI without Claude Code.

A worked example is in [`examples/advanced/`](https://github.com/drilonrecica/igris/tree/master/examples/advanced): the example plan with Verify profiles, Timeouts and Context paths, and the `igris.toml` that defines its profiles.

## Upgrade

```sh
brew upgrade igris                         # or: brew install drilonrecica/tap/igris
go install github.com/drilonrecica/igris/cmd/igris@v0.4.0
```

Or download the archive for your platform below, check it against `checksums.txt`, and put the binary on your `PATH`:

```sh
sha256sum --ignore-missing -c checksums.txt    # macOS: shasum -a 256 --ignore-missing -c checksums.txt
tar xzf igris_0.4.0_<os>_<arch>.tar.gz
install -m 755 igris ~/.local/bin/igris
igris version
```

Your v0.3 plans and configs work unchanged. A run interrupted under v0.3.x resumes normally, with a one-time warning that `igris.toml` changed since the interrupted run: `task_overdue` joined the default notification events, so the config's hash differs even if you didn't edit the file.

## Behavior changes

- **`Verify`, `Timeout` and `Context` are now column names igris reads.** If your plan already has a column with one of these names for something else (a command, an estimate, notes), `igris check` may now reject it. Rename the column (e.g. `Verify notes`), or let `igris adapt` do it. These columns no longer reach the session prompt as extra columns.
- **`task_overdue`** is in every channel's default `events`. If you list `events` yourself, add it to hear about overdue tasks.
- **`igris adapt`** keeps Verify, Timeout and Context cells as written and never invents profiles, timeouts or paths.
- Plain `igris check` is unchanged; the lint hints appear only with `--strict`.

## Known limitations

- Linux and macOS; Windows through WSL2 only, not yet verified on a real Windows machine.
- Release artifacts are not signed (SHA-256 checksums only).
